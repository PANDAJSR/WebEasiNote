# 04 元素规范（文本/图形/多媒体）

## 4.1 Text 元素

关键字段：
- 几何：`Id/X/Y/Width/Height/Rotation`
- 边框：`BorderThickness/BorderType`
- 内容：`RichText`
- 动画：`Animations`（可选）

`RichText` 当前读取：
- `ArrangingType`（Horizontal/Vertical）
- `SizeToContent`（Manual/Height/WidthAndHeight）
- `VerticalTextAlignment`（Top/Center/Bottom）
- `TextLines/TextLine/TextRuns/TextRun`

### TextRun 样式

支持：
- `FontFamily/Source`
- `FontSize`
- `FontStyle`、`FontWeight`
- `Foreground/ColorBrush`
- `Foreground/LinearGradientBrush`
- `Opacity`
- `Decoration`（None/Underline）
- `TextEffects`：`TextFrame/TextShadow/TextReflection`

### 文本行属性

支持：
- `TextAlignment`
- `TextMarker` + `TextMarkerStyle`
- `Indent/IndentLevel/IndentType/MarginLeft`
- `Direction`
- `LineSpacing` / `FixedLineSpacing`
- `SpaceBefore/SpaceAfter`

### 列表符号字体兼容

- `TextMarkerStyle/Char` 是与 `FontFamily/Source` 配套的字符，不可仅根据字体名称猜测符号。
- 样例 `10.1爱护身体.enbx` 第 7 页三个列表项均为 `TextMarker=Circle`、`Char=l`、`Source=Wingdings`、`FontSize=56`，官方显示为实心圆点。
- Web 将 Wingdings 的 `l`（`U+006C`，及符号字体私用区编码 `U+F06C`）转换为 Unicode `●`；`U+00D8/U+F0D8` 映射为 `➢`（`U+27A2`，带阴影的空心右箭头），不应替换成实心 `➤`。转换后使用普通字体，避免再次套用 Wingdings。
- 规则只匹配 Wingdings 本身（包含字体 URI 的 `#Wingdings`），不套用到 Wingdings 2/3；未知字符保留原字符及字体。显式 `TextMarkerStyle/Char` 优先于 `TextMarker`：同一课件第 15 页问题段落虽为 `TextMarker=None`，仍携带 `Char=Ø`、`Source=Wingdings`、`FontSize=53.333333333333336`，官方显示箭头；此时不能丢弃符号。只有没有自定义字符且 `TextMarker=None` 时才不绘制符号；其他列表类型按类型生成圆点、方块、编号等。
- 普通文本、图形内文本与思维导图共用符号解析规则。每段编号预先计算一次，避免重复渲染或文本倒影使编号跳号；符号替换不改写课件中的正文与 `Lines/LineProperty` 换行信息。

兼容细节：
- 行尾 `\r\n` 会按规则裁剪，避免重复换行
- 编辑态文本回写 `RichText/Text` 时按 CRLF（`\r\n`）拼接行，序列化后可能显示为 `&#xD;` + 换行
- 编辑态文本回写时，非最后一行的末尾 `TextRun/Text` 也会补 CRLF，以保持与 `RichText/Text` 的换行语义一致
- `TextLine/Lines/LineProperty` 按当前 `TextRuns` 文本长度重建 `StartOffset/Length`（空行保留 `Length=0`）
- 没有 `TextLines` 但有 `RichText/Text` 时会回退构造单行文本
- `Text` 元素的 `Id/X/Y/Width/Height` 等顶层字段按“直属子节点”读取，避免被 `Animations/Animation/Id` 等内部字段污染
- `SizeToContent=WidthAndHeight`（横排）在渲染阶段需要按文本实测宽度扩展容器，避免因初始 `Width` 偏小导致浏览器自动折行；行内 `TextRun` 采用不折行（`white-space: pre` + `word-break: keep-all`）更接近官方

## 4.2 Shape 元素

关键字段：
- 几何：`Id/X/Y/Width/Height/Rotation`
- 颜色：`Background/ColorBrush`、`Foreground/ColorBrush`
- 形状路径：`Path`
- 边框：`Thickness`、`LineType`
- 不透明度：`Opacity`
- 几何类型：`Geometry/PresetGeometry/GeometryType`
- 可选内联文本：`InlineText/RichText`
- 可选效果：`Effects/DropShadow`、`Effects/Reflection`
- 动画：`Animations`（可选）

### Path 兼容规则

- 支持希沃前缀 `F0/F1`：映射为 fill rule
  - `F0` -> `evenodd`
  - `F1` -> `nonzero`
- 若 Path 前导无合法 SVG 命令，会尝试从首个 `M/m` 恢复
- 路径数值允许科学计数法的大写 `E` 和小写 `e`（含正负指数），边界估算必须与 SVG/Canvas 的数值语法一致。样例 `10.1爱护身体.enbx` 第 1 页青色装饰矩形包含 `4.1733017042133724E-08` 和 `-3.552713678800501E-15` 等近零坐标；将 `E` 错当命令会算错边界和归一化偏移，使竖条被 SVG 裁剪。此规则同时用于 SVG 与静态栅格缓存的几何计算。

### 填充规则来源优先级

大致优先级：
1. Path 节点属性 FillRule
2. `FillRule` / `PathFillRule` 字段
3. `PathGeometry` 中 FillRule
4. `F0/F1` 前缀推断

### Geometry、Path 与 ShapePaths 的官方语义

静态反编译 `Cvte.Paint.Shell.dll`（EasiNote 5.2.4.10148）得到以下结论：

- `ShapeSaveInfo.Geometry` 是必需字段；载入时，官方读取 `Geometry.GeometryType` 并尝试解析为 `ShapeType`，已知类型由对应形状类创建和绘制。
- `ShapeSaveInfo.Path` 和 `ShapePaths` 在存储契约中均为可选字段。官方保存普通形状时会写入 `Path = GetShapePath()`；未知类型在没有自定义形状构造器时必须提供非空 `Path`，否则载入抛出异常。因此“Path 可选”不代表普通已保存课件通常没有 Path。
- 预设几何的调整值存放在 `Geometry/PresetGeometry/Adjusts`。官方按形状类型解释这些值；例如 `RoundRectangleShape` 保存最多三组调整值，每组含 `Id`、`ScaleX`，部分还含 `ScaleY`。不能将它们统一当作单个圆角比例。
- 直线类几何（`Line`/`LineArrowEnd`/`LineArrowStartEnd`/`DashLine`/`FreeLine`）例外：官方 `LineShape.SetGeometrySaveInfo` 直接用两个 `Adjust` 的
  `(ScaleX × Size.Width, ScaleY × Size.Height)` 作为线段两端点（两个端点的四个分量全为 0 时，第二点退化为 `(1, 1)`）。
  Web 端已按同样规则生成，因此 `Adjusts=(1,0)(0,1)` 这类斜线不再被画成水平线。
  实测语料 86 个线类形状中，63 个 `Line` + 4 个 `LineArrowEnd` + 2 个 `Line` 竖线依赖该规则修正。
- `ShapePaths` 是额外的多路径信息，`Paints` 则是运行时字段；官方 `ShapeElement` 从 `ShapePaths`/`Paints` 分别恢复附加路径和绘制填充。

Web 端的 `generatePresetGeometryPath` 仅是常见形状的近似兜底公式，不是官方几何实现的逐项复刻。对它未覆盖的类型，当前默认矩形回退可能造成错误外观；当 XML 有官方 `Path` 时优先使用该路径。自定义 `Custom_PPTX_*` 类型尤其应以样例中序列化的路径为准。

证据：本机官方程序集 `Cvte.Paint.Shell.dll` 的 `ShapeSaveInfo`、`ShapeElement`、`ShapeBase`、`LineShape`、`ShapesFactory`、`RoundRectangleShape` 反编译；样例 `slide_3_niuhe_e.xml` 中 `Custom_PPTX_Line` 与 `Custom_PPTX_RoundRectangle` 同时包含 `GeometryType` 和 `Path`。结论来自静态证据，未验证各形状在官方应用中的实际绘制像素差异。

### Shape 描边、虚线、箭头（官方语义）

以下取值全部来自 `Cvte.Paint.Shell.dll`（EasiNote 5.2.4.10148）中 `ShapeBase.SetSaveInfo` /
`SetDashStyle` / `RefreshPen` / `GetPenLineCap` / `GetArrowPoints` 与 `DashCollection` 的反编译结果，
Web 端实现见 `src/rendering/shape-stroke.ts`。

- 官方虚线数组（`DashStyle.Dashes`）单位是**线宽倍数**，不是像素：`Normal=[]`、`Dash=[2,2]`、
  `DotDash=[5,3]`、`LongDash=[10,2,2,2]`。Web 端换算为 `倍数 × 线宽 × 缩放` 的像素值，
  并配合 `vector-effect="non-scaling-stroke"`。
- `LineType → 虚线`：`Normal/StartArrow/EndArrow/DoubleArrow` 为实线；`Dash` 用 `[2,2]`；
  `DotDash` 与 `StartDotArrow/EndDotArrow/DoubleDotArrow` 用 `[5,3]`；`LongDash` 用 `[10,2,2,2]`。
- `PenSetting/DashStyle/Dashes` 存在时**直接覆盖**上面的线型虚线（实测值 `3.8,2.85`、`2.85,1`、`5,3`、`10,2,2,2`）。
- `Thickness` 只在 `0..100` 内生效，否则描边宽度为 0。
- `LineType=None` 时，**闭合图形**（`ShapeBase.IsClosed`）描边宽度为 0（完全不描边），未闭合图形保持实线。
  `IsClosed` 由形状类型决定：`Line/LineArrowEnd/LineArrowStartEnd/DashLine/FreeLine/Brace/Bracket`
  是开放图形；`FreeShape`、`Love/Cloud/Bomb/Thunder`、`UnKnown`（含 `Enum.TryParse` 失败的 `Custom_PPTX_*`）
  走 `ShapeFromStream` 按路径是否闭合判定；其余预设类型沿用 `ShapeBase.IsClosed=true`。
  路径闭合判定同样复刻 `FreeShapeRenderer.HasClosedSegments`：`z/Z` 只闭合「段数 > 1」或「唯一一段不是直线」的子图形，
  因此 `M0,0 L10,0 Z` 这类退化两点折线仍视为未闭合。
  实测语料中 `LineType=None` + 可见描边 + 有效线宽只出现 2 次且都是 `Line`（开放图形），因此该规则在本语料不改变画面，用于保证语义与官方一致。
- 线端（`stroke-linecap`）：`PenSetting/LineJoin` 缺省或 `Round` 时为 `Round`（官方 `IsSmoothJoin`）；
  否则闭合图形 + `LineCap=Flat` 时为 `Square`；其余取 `PenSetting/LineCap`（缺省 `Flat`）。
  线接（`stroke-linejoin`）为 `PenSetting/LineJoin ?? Round`，`DashCap` 固定 `Flat`。
- 箭头只由「线」类形状绘制：`ShapeType.Line/LineArrowEnd/LineArrowStartEnd` 由 `ShapesFactory` 创建 `LineShape`，
  `FreeLine` 创建 `FreeLineShape`，二者才调用 `GetArrowPoints`。
  `ShapeFromStream`（`Custom_PPTX_*`、`Love/Cloud/Bomb/Thunder`、`UnKnown`）的 `OnRender` 只画几何体，**不会绘制箭头**，
  即使 XML 里存在 `Line/TailEnd/Type=Arrow`。
- 箭头几何：`ArrowWidth = 5 × max(线宽, 2)`、`ArrowHeight = 2.5 × max(线宽, 2)`，以首末点（弦）确定朝向，
  绘制为 `pt1 → 尖端 → pt2` 的**开放折线（不填充）**，用描边色与描边线宽绘制。
  `<ArrowType>`（`Stealth/Oval/Triangle`）与 `Width/Length(Small/Medium/Large)` 对几何没有影响。
  `IsArrowDash=false` 时箭头用实线，否则跟随线型虚线。
- `LineArrowEnd/LineArrowStartEnd` 的工厂实例预置箭头；载入点划线时，官方据此先选择 `[2,2]`，
  再由显式 `PenSetting/DashStyle` 覆盖。显式空虚线数组覆盖为实线。箭头线接取 `LineJoin ?? Miter`。
- `FreeLineShape` 的箭头方向取首段 `t=0.05`、末段 `t=0.95` 的贝塞尔曲线点与对应端点的方向；Web 端同步采用该规则。
  `BezierLine/BezierLineArrowEnd` 虽在官方枚举中，但本版本工厂没有对应分支，未据此补充渲染规则。
- 实测语料：`LineType` 分布为 `None 22622 / Normal 332 / Dash 31 / EndArrow 18 / DoubleArrow 8 / DoubleDotArrow 4 / DotDash 4 / LongDash 3`；
  其中 38 个虚线类形状此前被渲染成实线或错误的虚线段长，现已按官方 `DashCollection` 修正。
  声明了箭头的线类形状仅 4 个（其余 34 个箭头声明落在 `Custom_PPTX_Line` 上，官方同样不绘制）。

### 原生形状路径、分层与局部坐标（5.2.4.10148）

- `Geometry` 可以包含 `PresetGeometry` 或 `CustomGeometry`；`FreeLine` 的类型和原始曲线路径存放在后者。开放的 Line、FreeLine、Brace、Bracket 不填充，即使 `Background` 是不透明颜色。
- `GetShapePath()` 可以拼接多个 WPF 几何字符串，因此 `F0/F1` 可出现在路径中间。转换为 SVG 时必须去除全部填充规则指令，不能只处理首个前缀；几何组仍需保留各自语义。
- 已知原生形状的序列化路径保留元素局部坐标，不按控制点包围盒拉伸或平移。`Bubble` 的思考气泡、`RectangleMark` 的引线可以越出 `Width/Height`；SVG 与静态缓存均不按元素矩形裁剪。`FreeLine` 使用二次/三次贝塞尔实际极值归一化，不能用控制点边界代替。
- `Bracket` 使用半径 `(width, ScaleY × min(width,height))` 的两段椭圆弧；`Brace` 使用半径 `(width/2, ScaleY × min(width,height))` 的四段椭圆弧，分别限制纵向半径至 `height/2`、`height/4`。
- `SmilingFace.GetShapePath()` 顺序为脸、双眼、扩宽后的嘴。脸用背景画刷，眼和嘴用前景色；前景为无色时用白色。不能把五官当成透明孔洞。
- `Fire` 的两个轮廓分别绘制背景色和 `#4CFFFFFF` 内芯覆盖层。
- `Medal` 的七个轮廓按 `0,3,4,1,2,5,6` 绘制：前三层为背景色，之后依次为 `#32000000`、`#19FFFFFF`、`#32000000`、`#32000000`。
- `Scroll` 序列化顺序为整体底色、头部高光、头部暗部、尾部高光、尾部暗部；高光为 `#19FFFFFF`，暗部为 `#32000000`。
- `Banner` 序列化顺序为完整底色、左尾翼、右尾翼、左折角、右折角；尾翼覆盖 `#4B000000`，折角覆盖 `#64000000`。
- `RotationArrow` 的序列化轮廓为前半箭头和后半弧带；两者均填背景色，后半弧带额外叠加 `#32000000`。此处为导出轮廓顺序，不能直接套用内部 `OnRender` 字段顺序。
- 上述半透明明暗层在背景无色时不绘制。复合色形状暂走 SVG，避免只支持单色的静态缓存丢失分层。

证据：REA 静态成员记录 `ev_45dfdfbdff00d8109a5cb27cac3cc1151f09a7ee8e8226b179d15f2bf7bede9f`；ILSpyCmd 11.1.0.9782 对 `Cvte.Paint.Shell.dll` 的各形状类反编译。DLL SHA-256 为 `481012f25286ac000ac14b15ab1a534476824e921e5b8b034f229ca159c74277`。`形状.enbx` 的第二页包含 41 个原生形状，第一页保存对应官方效果图，可用于整页对照。已保存路径的兼容不代表所有缺省 Path 的复合预设几何已实现。

## 4.3 Picture 元素

- `Alpha`
- `Rotation`
- `DisplayRegion/Rectangle`
- `MetaData/PictureSize`

解析细节：

### 相框与特效（5.2.4.10148）

`媒体.enbx` 的图片资源本身为 PNG/JPEG；缺失的外观来自样式字段，不是图片解码失败。

- 现代相框位于 `Style/PictureRahmenStyle`：`RahmenStyle`、`LineRahmenThickness`、
  `LineRahmenBrush/ColorBrush`、`ImageRahmenWidthIndex`。现代节点优先于旧平铺
  `PictureRahmenType` / `RahmenType`、`RahmenThickness`。`PicturePresetStyle=Empty` 不清除手动相框。
- 已支持 `NormalFrame`、`DotDashFrame`、`LongDashFrame`、`RectFrame`、`RoundRectFrame`、
  `EllipseFrame`、`CurveRhombusFrame`。线框使用保存颜色和宽度，零宽不画；实际描边为保存宽度 + 1，
  虚线数组分别为 `[5,3]`、`[10,2,2,2]`，单位为实际描边宽度。边框向原图外扩，不挤压裁剪区域。
- 艺术框宽度为 `ImageRahmenWidthIndex × 10`。矩形框使用官方 60×60 PNG 九宫格（切片 29，
  外边距 `-18-宽度`）；其余三个形状框以白描边及轻微阴影呈现，同时裁剪主图。
  `CurveRhombusFrame` 不是菱形，而是仅左上/右下圆角的矩形，参考几何 405×264、角半径约 72。
- `Style/Effects/DropShadow`：`Offset`、`Angle`、`Opacity`、`BlurRadius`、`ShadowBrush/ColorBrush`。
  页面坐标偏移为 `dx=sin(Angle)×Offset`、`dy=-cos(Angle)×Offset`（角度制），SVG 高斯模糊标准差取半径的一半。
  阴影按图片/相框的几何轮廓填充，而不是对透明图片像素作 alpha 投影。
- `Style/Effects/PerspectiveShadow`：读取六项 `ShadowMatrix`（WPF 顺序，与 SVG matrix 一致）、
  `OffsetY` 及同样的透明度、模糊、画刷；以旋转后外接框底边锚定变换，再在页面坐标模糊。
- `Style/Effects/Reflection`：读取 `OffsetY`、`Opacity`、`OpacityMask/LinearGradientBrush` 的
  `StartPoint`、`EndPoint`、`Opacity`、`GradientStops`。停止点格式为以空格分隔的 `#AARRGGBB,位置`。
  倒影复制裁剪后主图和相框，在旋转后的页面坐标上下翻转，并保留渐变蒙版。
  真实样本为 0/4 间距、三种渐变长度共六种，透明度为 0.35。
- `ElementEffects/ReflectionTypeName` 等菜单预设可能过时，不能据此合成实际不存在的倒影；
  实际特效以 `Style/Effects` 为准。主图、相框与特效共同消费 `Alpha` 并统一缩放。

## 4.5 Flash 元素

官方实现：`Cvte.Paint.FlashPlayer.Flash : MultimediaElement`，契约标签 `<Flash>`，
保存契约 `[SaveInfoContract("Flash")]`（`FlashSaveInfo`）。

关键字段：
- `Source`（`id://...`，必填；指向 `Resources/*.swf`）
- `FlashName`（原始文件名，默认 `""`）
- `FlashWidth` / `FlashHeight`（SWF 舞台原生尺寸，默认 **99**）
- `Width` / `Height`（**图标按钮**的尺寸，通常 64×64）
- `Rotation`、`IsLocked`、`CanClone`、`HasMask`、`RotateOrigin`
- `SaveInfoMetadata`（`SupportsFallback`、`ImportanceLevel`）
- `Animations`（可选，真实课件中常缺省）

真实节点的典型形态（`Slides/Slide_1.xml`）：


尺寸语义（易错点）：
- `Width/Height` 只决定红圆图标在页面上的大小，与 SWF 内容无关；实测 64×64、81×81、63.688×63.688。
- `FlashWidth/FlashHeight` 是舞台尺寸，官方 `FlashContainerGrid_OnSizeChanged` 用
  `new Rect(0,0,FlashSize).FillInto(outerRect)` **等比 letterbox** 填充，不拉伸变形；
  元素另有 `[Transform(FixedRatioScaleOnly)]`，只允许等比缩放。
- 实测舞台尺寸出现 800×600、700×492、320×240。

渲染约定（WebEasiNote）：
- 图标复刻官方 `FlashElementContent.xaml`：64×64 `Viewbox`、红圆 `M0,32 A32,32 0 0 1 64,32A32,32 0 0 1 0,32`
  （`#E34A4A` 填充 + 2px 白描边 + `BlurRadius=8/ShadowDepth=0/Opacity=0.3` 阴影）、
  居中 32×32 白色 `Opacity=0.8` 字形，默认字母 f，悬停切播放三角。
- 点击图标在页内 antd `Modal` 中用 Ruffle 播放（官方为独立 `FlashPlayerWindow`，此处为有意偏离）。
- `Source` 缺失或资源未加载时渲染「Flash 资源未加载」占位框（与 Video 一致），不静默丢弃元素。

限制：
- Ruffle 无帧级 API（`currentFrame`/`totalFrames`/`gotoFrame`），官方的帧进度条、点击跳帧与
  末帧重载（`RePlay()`）无法复刻，改为播放/暂停 + 重播。
- SWF 通过 `blob:` 加载，内部 `loadMovie` 等相对路径外部资源不可用。
- `HasMask` 对弹窗播放无效。
