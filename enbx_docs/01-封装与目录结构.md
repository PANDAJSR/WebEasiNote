# 01 封装与目录结构

## 1.1 ENBX 本体

ENBX 在本项目中被视为 ZIP 容器。

核心入口文件：
- `Board.xml`
- `Document.xml`
- `Reference.xml`
- `Slides/Slide_*.xml`
- `Resources/*`

解析入口代码：
- `src/enbx/parser.ts` 中 `parseENBXFile`
- 对已解压目录同样支持（`parseExtractedFolder`）

## 1.2 目录结构（已观测）

典型结构：

```text
课件根目录/
  Board.xml
  Document.xml
  Reference.xml
  SaveInfoMetadataFile.xml
  Slides/
    Slide_0.xml
    Slide_1.xml
    ...
  Resources/
    *.png/*.jpg/*.mp4/*.mp3/*.svg/无后缀资源
  thumbnail.png (可选)
```

说明：
- `SaveInfoMetadataFile.xml` 在当前项目中不参与解析，仅用于能力线索
- `thumbnail.png` 不参与解析渲染
- `Resources` 下存在“有扩展名/无扩展名”两类资源文件

## 1.3 幻灯片组织方式

当前实现按 `Slides/Slide_数字.xml` 文件名排序加载。

这意味着：
- 实际渲染顺序以文件编号为主
- `Board.xml` 中的 `Slides/Item` 同时提供了逻辑页 ID 列表

云端 HTTP 文件源（`src/courseware/http-courseware.ts`）采用更严格的映射：

- 已检查样本 `test_cases/测试希沃白板格式.enbx`，页文件从 `Slide_0.xml` 开始连续编号，正文 `<Id>` 与 Board 同序 Item 对应。
- 该观察不等于所有 ENBX 版本的格式保证。HTTP 按需入口要求页文件数与 Board 数量一致、编号从 0 连续，并在每页 XML 到达后核对正文 ID；不匹配时明确报错，允许关闭插件懒加载后按原全量入口打开。
- 未加载项保留目录身份、尺寸、预览与状态，不作为当前正文。首屏只等待 manifest、Board、存在于清单中的 Reference 和目标页 XML。
- Reference 不在清单时允许为空；清单中列出但下载失败时不当作缺省文件吞掉错误。图片和媒体使用同源文件 URL，云媒体默认不预载完整文件。
- 云课件导出必须补全清单内所有文件，再应用已加载页面的编辑补丁；任一文件失败不得生成残缺课件。

## 1.4 文件缺失容错

当前实现：
- `Board.xml` 缺失：直接判定无效课件
- `Document.xml` 缺失：允许，元数据使用默认值
- `Resources` 缺失：允许，资源计数为 0
- `Slides` 缺失：允许，最终无页面
