# 07 解析流程与实现约定

## 7.1 端到端解析流程

1. 读取 ENBX（ZIP）或已解压目录
2. 解析 `Reference.xml`，建立 `resourceId -> filePath` 映射
3. 解析 `Board.xml`/`Document.xml` 生成课件元数据
4. 读取并排序 `Slides/Slide_*.xml`
5. 每页解析：背景 -> 转场 -> 动画顺序/元素动画 -> 元素列表
6. 渲染阶段按 `resourceMap` 把资源 ID 绑定到 blob URL，并按点击/键盘步进消费元素动画（当前支持 `FadeIn/FadeOut/Flicker/DiagonalWipeIn/BlindIn/TranslateIn/TranslateFadeIn`，触发器支持 `Click/Before/After` 与 `TriggerSource`，并消费 `DiagonalWipeIn/TranslateIn/TranslateFadeIn` 的 `Orientation` 与 `BlindIn` 的 `Direction`；`TranslateFadeIn` 还会消费 `Path`，并从子动画 `Line/Path` 回退取值）

## 7.2 类型与问题模型

核心类型：
- `CoursewareMetadata`
- `SlideData`
- `SlideElement`（联合类型）
- `SlideIssue`

问题分类：
- `unknown-element`
- `unknown-parameter`
- `missing-font`

`missing-font` 在 Viewer 阶段扫描文本字体可用性后追加。

## 7.3 颜色规则

`parseColor` 规则：
- `#AARRGGBB`
  - 默认返回 `#RRGGBB`
  - `preserveAlpha=true` 时返回 `rgba(...)`
- `#RRGGBB` 原样返回

## 7.4 字体与字号

- 字体来源通常是 `FontFamily/Source`
- 会做别名字体候选展开（中文字体与平台字体映射）
- 字号转换函数存在，但当前比例系数为 `1`

## 7.5 行距规则

- XML `LineSpacing` 会映射到 CSS `line-height` 倍数
- 当前换算：`1 + lineSpacing * (1/8)`
- `FixedLineSpacing` 优先级更高（按像素）

## 7.6 资源加载约定

- 资源引用统一采用 `id://<resourceId>`
- 通过 `Reference.xml` 找到 `Target`
- ZIP 模式直接按完整路径读取
- 文件夹模式按 `Target` 最后文件名在 `Resources/` 查找

注意：
- 文件夹模式若存在重名文件，理论上可能命中错误资源

## 7.7 导出回写约定

- 编辑后导出 ENBX 时，优先采用“字符串片段替换”写回元素 XML，而不是整页 DOM 重新序列化
- 这样可最大程度保留原始文本节点细节（如多行文本换行符、实体写法、CDATA 风格）并降低格式漂移风险
- 若字符串替换无法定位目标片段，再回退到 DOM replace + serialize 兜底
- 编辑态拖拽改坐标（`X/Y` 或 `Location`）同样优先做“节点片段替换”，避免把 `RichText/Text` 中的实体写法（如 `&#xD;`）改写为其他等价值形式
- 编辑态缩放改尺寸时，会同步回写 `Width/Height`；若元素包含 `Size`（`w,h`）字段也会一并同步，位置字段仍按 `X/Y` 或 `Location` 规则更新
- 解析 `Slide.xml` 时会尽量保留顶层元素的原始 XML 片段，导出时优先按“原片段 -> 新片段”替换，减少因查找失败触发整页重序列化
## 7.8 后续扩展建议

建议优先级：
1. 按 `unknown-element` 统计频率补齐元素解析器
2. 为 `ActivityItem/HanziCard/SolarSystem` 建立最小可视化占位解析
3. 在现有 `FadeIn/FadeOut/Flicker/DiagonalWipeIn/BlindIn/TranslateIn/TranslateFadeIn` + `Click/Before/After/TriggerSource` 基础上继续补齐其他 `Animations` 类型与触发器
4. 为 Group 增加旋转/变换矩阵支持
5. 完善转场键值（如 `CircleOut`、`Magic`）

## 7.9 浏览与放映的静态绘制缓存

- 文件资源、元数据、页面共用同一个 JSZip 实例。逐页解析之间让出主线程；目前仍在进入查看器前解析全部页面，并未实现首屏优先或 XML Worker。
- ZIP 与文件夹均优先使用 `SlideThumbnails/Slide_n.png` 作为懒加载预览；缺失时显示页码，避免缩略图重复挂载正文元素。预览是文件内嵌内容，可能与手工修改后的正文不同。
- Group 不进入扁平绘制模型，不再重复序列化整个 Group 子树。保留整页原始 XML、顶层片段和叶元素 XML；叶元素不再额外全量格式化缩进。
- 只合并连续且至少包含 32 个元素的安全静态 Shape 段，保持原 Z 顺序。组合、锁定本身不代表可缓存。
- 首版仅接受纯色路径、无文字、无描边、无阴影/倒影、整体不透明的 Shape。渐变、媒体、表格、未知参数及效果保持原渲染。`HasMask=True` 禁止缓存；`ShowRotateOrigin=False` 是关闭旋转原点显示的状态，可进入白名单，True 仍回退。
- 动画 `targetId`、`sourceElementId`、`triggerSource` 命中的元素以及其对应组后代均排除，即使动画效果尚未支持。组自身有动画或未知行为时整组后代排除。外部逐元素样式和可见性状态覆盖同样触发回退。
- 原始模型、ID、组祖先关系和命中检测保留；缓存只替代绘制。SVG 和 Canvas 共用 `shapeGeometry.ts`，此轮保持现有路径归一化行为，未变更官方几何扩展的解释规则，也不删除 `CustomGeometryInfoExtension`。
- Worker + OffscreenCanvas 生成 ImageBitmap，冷缓存期间保留矢量，成功后卸载对应 SVG。热缓存同步复制，避免再次挂载整段矢量。浏览器能力缺失、生成失败或 15 秒超时均回退。
- SHA-256 指纹包含当前实际使用的路径、颜色、变换、填充规则和绘制顺序，排除元素 ID；页面宽高和分辨率参与缓存键。任何实际路径精度差异都应产生不同指纹。实测第 5 页颜色不同，指纹独立；第 15 页的 `Path/ShapePaths` 与普通页完全相同，差异在当前未使用的几何扩展，因此当前可共享。以后支持几何扩展时，必须同步更新绘制计划与指纹内容。
- 分辨率按显示比例 × DPR 分半档取整，最多 3 倍且单幅不超过 1600 万像素。ImageBitmap 使用 64 MiB LRU 预算；正在复制的引用受保护，活动页面画布另占像素存储。最多 8 个待处理任务。
- 翻页仅挂载当前页与转场相关页；已访问页面的跨页视频仅保留 video 元素，直到停止页，不为视频保留整页背景。
- 文件重载、关闭、查看器卸载时终止任务并清空缓存；异步结果有版本与组件销毁检查。离开页面释放其画布存储。
- 本轮不增加编辑模式功能；已有编辑入口沿用原元素绘制路径。

验证命令：`pnpm test`、`pnpm build`。本地真实课件诊断：

```powershell
pnpm analyze:performance '<课件.enbx>' '<报告目录>'
```

诊断使用 happy-dom、Skia Canvas 和 resvg，不等同于浏览器帧率测试。像素差按白底合成比较，避免将透明边缘不可见 RGB 的差异误判为可见差异。不得据此声称与官方 EasiNote 完全一致。
