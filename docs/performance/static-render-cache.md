## 翻页仍卡顿的补充定位

首轮优化遗漏了画布之外的主线程开销。`Viewer.tsx` 原先将完整问题列表直接写成 Modal 的 JSX 子节点；即使 `open=false`，父组件每次翻页渲染时也会先执行 `filteredIssues.map` 创建全部 React 元素，再把这些子节点交给 Modal。Modal 不显示并不能阻止这一步。问题类型的三次全量计数也在每次渲染中执行。

按当前 `KNOWN_PARAMETERS` 和 `Group/Elements` 递归规则统计，实际课件的 18 页共生成 311,674 条未知参数诊断记录。重复的图形字段会放大这个数量。将旧列表生成函数原样提取出来，按此真实数量构造同类记录，在本机 Node/React 开发环境单次创建列表行耗时 2168.36 ms；此数值为局部复现，未计入其他渲染和垃圾回收，也不能当作浏览器翻页耗时。

已将问题面板拆成独立组件：关闭时直接返回，不遍历、计数、排序、筛选问题，也不创建列表行；打开时才计算数据，并且每页只挂载 100 条记录，筛选会回到第一页。没有元素编辑时直接复用原页面数组，避免无效数组复制影响缓存生命周期。

新增回归测试用包含 311,674 条记录的 Proxy 数组拦截任何内容访问：关闭状态连续 20 次渲染，读取次数为 0，总耗时约 2.3 ms。打开、分页到 100/100/5 条、切换筛选与关闭清理均通过。全套 11 项测试和生产构建通过。

本次修复消除了已复现的隐藏问题列表开销。Worker 冷缓存期间的 SVG 回退仍然保留；缓存未命中、媒体首次解码和转场耗时仍需在真实浏览器分别验证，不据此宣称每次翻页已达到某个时延。
